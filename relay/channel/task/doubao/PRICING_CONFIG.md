# Doubao Seedance 模型计费配置指南

## 概述

Doubao Seedance 系列模型支持差异化计费，根据不同的参数（分辨率、视频输入、音频）应用不同的价格倍率。

## 计费原理

系统采用 **基准倍率 × 差异化倍率** 的方式计费：

1. **管理员配置**：为每个模型设置"基准场景"的 `ModelRatio` 或固定价格（通过后台渠道配置）
2. **系统自动调整**：根据用户实际请求参数，系统自动应用 `OtherRatios` 调整最终价格
3. **最终计费** = `BaseTokens × ModelRatio × GroupRatio × OtherRatios乘积`

使用固定价格时，`BaseTokens × ModelRatio` 替换为管理员配置的单次基准价格，
`OtherRatios` 仍会在任务提交时生效。例如 Seedance 1.5 Pro 的固定价格应填写
“有声视频单次价格”，无声请求会自动乘以 `0.5`。

以下已确认价格一致的 Agent Plan 稳定别名与标准方舟版本化模型共用规则：

- `doubao-seedance-1.5-pro` → `doubao-seedance-1-5-pro-251215`
- `doubao-seedance-2.0` → `doubao-seedance-2-0-260128`
- `doubao-seedance-2.0-fast` → `doubao-seedance-2-0-fast-260128`

标准方舟的版本化模型 `doubao-seedance-2-0-mini-260615` 使用下文的
14/23 元差异化规则。Agent Plan 稳定别名 `doubao-seedance-2.0-mini`
仍保持独立，不自动继承标准方舟价格。

## 各模型配置方案

### 1. doubao-seedance-2-0-260128

**官方价格**：
- 480p/720p + 不含视频输入：**46元/百万token**（基准）
- 480p/720p + 含视频输入：28元/百万token
- 1080p + 不含视频输入：51元/百万token
- 1080p + 含视频输入：31元/百万token

**配置方案**：
```
基准场景：480p/720p 不含视频输入
ModelRatio：46 ÷ 7.3 ÷ 2 ≈ 3.150685 倍率
```

**自动调整规则**：
- ✅ 用户选择 **480p/720p + 不含视频** → 无调整，使用基准倍率 3.150685
- 🔽 用户选择 **480p/720p + 含视频** → `video_input = 28/46`，实际倍率 ≈ 1.917808（对应 28元）
- 🔼 用户选择 **1080p + 不含视频** → `resolution = 51/46`，实际倍率 ≈ 3.493151（对应 51元）
- 🔽🔼 用户选择 **1080p + 含视频** → `resolution × video_input = (51/46) × (31/51) = 31/46`，精确对应 31元

## 配置步骤

1. **进入渠道配置页面**
   - 在管理后台找到 Doubao Video 渠道配置

2. **为每个模型配置基准倍率**
   - 参考上述"配置方案"中的 `ModelRatio` 值
   - 在"模型倍率"字段中输入相应的值

3. **验证配置**
   - 系统会自动根据用户请求参数应用差异化倍率
   - 可在日志中查看最终计费的 `OtherRatios`

## 价格换算公式

```
元/百万token → 倍率
倍率 = 价格(元) ÷ (7.3 × 2)
     ≈ 价格(元) × 0.068493

说明：
- 1 USD = 7.3 RMB
- 1 倍率 = $0.002/1k tokens = $2/1M tokens
- 1 元/1M tokens = (1/7.3) USD/1M tokens = (1/7.3)/2 倍率 ≈ 0.068493 倍率
```

## 技术细节

### OtherRatios 命名规范

- `resolution`: 分辨率倍率（1080p 相对于 480p/720p 的加价）
- `video_input`: 视频输入折扣（含视频相对于同分辨率不含视频的折扣）
- `audio`: 音频折扣（无声相对于有声的折扣）

### 参数提取规则

1. **分辨率**：
   - 优先从 `metadata.resolution` 读取
   - 其次从 `req.Size` 解析（如 "1920x1080"）
   - 默认 "720p"

2. **视频输入**：
   - 检测 `metadata.content` 数组中是否存在 `type = "video_url"` 且嵌套 `video_url.url` 非空的元素

3. **音频**：
   - 从 `metadata.generate_audio` 读取布尔值
   - `true` 或未传使用有声基准价（上游默认值为 `true`）；仅显式 `false` 使用无声倍率 `0.5`
   - 建议调用方始终显式传入该字段，便于计费日志清晰可审计

## 常见问题

### Q1: 如何验证配置是否生效？

A: 可以在日志文件中搜索 `OtherRatios`，查看系统为不同请求应用的倍率。

### Q2: 为什么有些场景没有 OtherRatios？

A: 当用户请求的参数与基准场景一致时，`OtherRatios` 为空或为 1.0，表示无需调整。

### Q3: 如何处理价格调整？

A: 如果各档价格同比例变化，只需更新渠道配置中的基准 `ModelRatio`。如果档位之间的相对价格发生变化，还需同步更新 `seedanceBillingConfigs` 中的差异倍率及对应测试。

### Q4: 系统如何处理多个倍率叠加？

A: 多个 `OtherRatios` 会相乘，例如：
- 基准倍率 = 3.150685
- 1080p 倍率 = 51/46
- 1080p 视频输入倍率 = 31/51
- 最终倍率 = 3.150685 × (51/46) × (31/51) ≈ 2.123288，精确对应基准价的 31/46
